# Agent 与工具调用 课程示例笔记

这份文件是本实验自带的可修改示例资料，不是外部论文或课程官方讲义。

## 单用途 Agent
本实验的 Agent 面向研究生研读资料与安排阅读任务这一具体场景。
普通对话可以直接生成文字；本实验要求先读取本地资料或任务数据，再生成有依据的答复。
Agent 的核心组成包括系统提示词、模型接口、工具注册表、上下文消息和编排循环。

## Function Calling
Function Calling 通过 JSON Schema 向模型描述工具名称、用途与参数结构。
模型返回 tool_calls，应用校验参数并执行对应函数，再把结果作为 role=tool 的消息送回模型。
每条工具结果通过 tool_call_id 与模型发起的调用对应，模型获得上下文后决定继续调用或最终回答。
工具调用并不是让模型直接执行 Python：实际执行权属于应用的工具注册表。
参数校验可以阻止未知字段、非法范围和错误类型进入工具实现。

## 编排与可观察性
编排循环先搜索和读取原文，也可以分析真实 CSV；模型从内容中提炼主题、难度与先修关系，再调用规划工具检查覆盖和时间预算。
循环应设置最大轮数与调用次数，防止模型无限重试。
保存工具名、参数、结果、轮次、耗时有助于解释回答依据并复现问题。
真实模型模式负责理解需求、选择工具和总结，规则演示模式仅用于离线验证协议和工具。
